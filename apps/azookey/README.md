# AzooKeyカスタム入力表の同期

`apps/azookey/CustomInputTable/custom_input_table.tsv` を正本として、AzooKeyのコンテナ内にある表へ一方向に同期します。辞書、入力履歴、その他の設定は対象外です。前回同期ハッシュはコンテナ内の `CustomInputTable` ディレクトリに拡張属性1件で保持します。`~/Library/Application Support/my.azookey.sync`、永続ログ、同期処理のコピーは作成しません。

## 初回設定と手動同期

初回設定ではAzooKeyの設定画面を閉じ、入力メソッドを終了してください。リポジトリのルートで次のコマンドを実行します。

    bash apps/azookey/azookey-setup.sh

正本の表を編集した後や、別端末からのiCloud同期が終わった後も、同じコマンドを実行してください。

新しい許可や別の利用者向け同期コマンドは必要ありません。

## 同期と競合

セットアップは既存のリンク先がdotfilesの正本と一致する場合だけ、リンクをコンテナ内の実ディレクトリへ移します。保存先がない場合や空の場合は初期化します。表以外の資産、想定外のリンク、異なる保存先データがあれば置き換えず停止します。正本の表は削除・変更しません。

同期先が前回の同期内容から独立して変更されていた場合は、その内容を保全して以降の同期を止めます。正本TSVが不正・欠落・読取不能の場合、同期状態が欠落・破損している場合、コピーや原子的置換に失敗した場合も既存表を上書きしません。状態書込み後に失敗した場合は、同じコマンドを再実行すると整合を確認できます。

内容の差分は次で確認できます。

    git diff -- apps/azookey/CustomInputTable/custom_input_table.tsv

処理結果と停止理由は実行時に表示します。表の内容をログや画面へ出しません。GUIで保存した変更はdotfilesへ戻しません。編集元はdotfiles側の正本に統一してください。

## 旧資産の整理

セットアップは既知の旧LaunchAgentを停止して定義を削除し、同期成功後に旧コピー・ログ・状態・退役済み定義を個別に削除します。旧資産が既知の形式と異なる場合や用途不明の資産がある場合は、保全して停止します。成功後、`my.azookey.sync` フォルダーは残りません。

同期状態として残るのは、コンテナ内のCustomInputTableディレクトリに付く `my.azookey.sync.last-synced.sha256` 属性1件だけです。フォルダー削除に失敗した場合は成功として扱わず、その理由を表示します。

## AzooKeyでの反映

同期先の表を置き換えた後、起動中のAzooKeyがいつ表を読み直すかは未確認です。変換セッションを作り直した場合と、AzooKeyを次回起動した場合を分けて実入力で確認してください。このコマンドはAzooKeyを終了・再起動しません。
